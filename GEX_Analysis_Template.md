# Регламент GEX-аналитики v2

Этот документ задаёт единый стандарт подготовки аналитики по опционным уровням CME для дашборда и графика MT5.

## 1. Режим работы

- Аналитика создаётся **только по явному запросу пользователя**, а не автоматически каждый день.
- Дневной отчёт относится только к указанной торговой дате `analysis_date`.
- Недельный отчёт создаётся отдельно по запросу и хранится по дате понедельника `week_start`.
- Отсутствие отчёта за выбранную дату или неделю — нормальное состояние. Старый отчёт нельзя подставлять вместо отсутствующего нового.
- Новый отчёт дописывается в архив, не удаляя отчёты за другие даты.

## 2. Главный принцип: аналитика и индикатор используют одни уровни

Единственный источник числовых уровней для текста — подготовленный блок `indicator_levels`, построенный теми же правилами, что и индикатор MT5.

Блок не пересчитывается агентом из CSV. Его экспортирует `CME_GEX_Levels_Indicator` после применения фактических настроек графика: порога GEX, лимита числа строк, дистанционных фильтров, обязательных ролей и реального `fw_offset` по дневной цене MT5.

Запрещено:

- повторно вычислять видимые уровни по собственному порогу;
- использовать универсальный фильтр `40%`, `50%` или `60%`;
- называть числовой уровень, которого нет в `indicator_levels`;
- смешивать исходные страйки CME и адаптированные цены MT5;
- подменять отсутствующий Zero Gamma ближайшим страйком;
- переносить старый отчёт на новый день только потому, что совпал день недели.

Если готовый блок `indicator_levels` не предоставлен, полноценный сценарный отчёт не составляется. Допустим только диагностический ответ с перечнем недостающих данных.

### Получение точного блока

1. Запустить расчётный конвейер и дождаться появления CSV нужной даты.
2. Обновить индикатор на графике MT5. При успешной отрисовке он создаёт файл `MQL5/Files/GEX/IndicatorLevels/GEX_<ASSET>_<YYYY-MM-DD>.json`.
3. Получить манифест одним из способов:

   - API: `/api/indicator-levels?currency=XAU&date=2026-08-03`;
   - CLI: `python Dashboard/indicator_levels_store.py XAU 2026-08-03`.

4. Проверить, что `asset`, `report_date`, `coordinate_system = MT5_SPOT` и `source_csv` относятся к запрошенному отчёту.

API и CLI используют только точное совпадение даты. Отсутствующий манифест нельзя заменять последним доступным файлом.

## 3. Обязательный входной контракт

Перед анализом должны быть доступны:

### Паспорт отчёта

- `schema_version`;
- `analysis_date` для дневного отчёта либо `week_start` и `week_end` для недельного;
- `generated_at` с часовым поясом;
- `asset`;
- `source_csv_date` и имя исходного файла;
- контрольная цена спота MT5 и время её фиксации;
- фьючерсная контрольная цена CME;
- `fw_offset`, его источник и статус применимости.

### Контекст экспираций

- `Daily_Month`, `Daily_Expiry`, число дней до экспирации;
- `Global_Month`, `Global_Expiry`, число дней до экспирации;
- признак смены дневного или глобального контракта относительно сравниваемой даты;
- `Estimated_Expiry_Types`, если поле доступно.

### Контроль качества

- `Quality_Status` и `Quality_Reasons`;
- `Anomaly_Status`, `Anomaly_Codes`, `Anomaly_Details`, `Anomaly_Baseline_Date`;
- `Gamma_Flip_Status`;
- статусы контрольных цен, IV и форвардного сдвига.

### Готовая карта `indicator_levels`

- текущий спот;
- Zero Gamma, если он существует;
- Daily Call MDD и Daily Put MDD;
- Global Call и Global Put;
- Max Absolute Gamma;
- R68 High/Low и R95 High/Low;
- тот же список видимых GEX/AG-уровней, который передан индикатору, вместе со знаком, величиной, относительной силой и назначенной ролью.

Манифест также фиксирует параметры отбора в объекте `selection`, источник и значение сдвига в `market`, экспирации, статусы качества и диагностические поля IV. Это позволяет проверить, почему конкретный уровень присутствует или отсутствует на графике.

Индикатор сам применяет разные пороги, лимиты и дистанции для разных активов. Аналитика принимает итоговый список как данность и не заменяет эти правила собственным фильтром.

## 4. Проверка координат уровней

Все цены в основном тексте и торговых сценариях приводятся в координатах спот-графика MT5.

| Тип уровня | Цена на графике MT5 |
|---|---|
| Обычный GEX/AG, Global Call/Put, Max AG | `strike + fw_offset` |
| Zero Gamma | `gamma_flip + fw_offset` |
| Daily Call MDD | `strike + fw_offset + Daily_Call_Settle` |
| Daily Put MDD | `strike + fw_offset - Daily_Put_Settle` |
| R68/R95 | `значение диапазона + fw_offset` |

Эти формулы нужны для аудита, но агент не должен вручную пересчитывать уже готовый `indicator_levels`. Исходный CME-страйк разрешено указывать только в служебной колонке таблицы, если он передан во входных данных.

## 5. Правила сравнения с предыдущим отчётом

- Сравниваются только одинаковый актив, продукт и одна и та же экспирация.
- При смене `Daily_Expiry` дневные изменения считаются началом нового цикла, а не продолжением старого.
- При смене `Global_Expiry` глобальные уровни сравниваются только внутри нового глобального цикла.
- Изменение OI и изменение GEX описываются раздельно: рост одного показателя не доказывает рост другого.
- Смена знака GEX фиксируется только по одному и тому же исходному страйку и сопоставимому контракту.
- Если сопоставимая предыдущая дата отсутствует, в отчёте прямо пишется: «сопоставимого предыдущего среза нет».

## 6. Корректная интерпретация

- **Zero Gamma** — расчётная граница режима, а не гарантированный триггер направления. При статусе `NO_CROSSING` уровень отсутствует.
- **R68/R95** — статистические диапазоны ожидаемого движения на основе доступной IV. Это не доказанные стены ликвидности.
- **Max Absolute Gamma** — узел максимальной абсолютной гаммы. Его роль магнита, поддержки или сопротивления определяется знаком GEX, положением цены, соседними уровнями и экспирацией; роль не назначается автоматически.
- **MDD** — расчётные уровни с учётом settlement-сдвига. Их нельзя заменять исходным страйком.
- **Gamma wall** допустимо называть только плотную группу подтверждённых видимых уровней одного характера.
- **Gamma hole/void** допустимо указывать только при наличии рассчитанной плотности уровней, подтверждающей разреженный диапазон.
- Формулировки о действиях дилеров являются гипотезой рыночной механики. Нельзя представлять их как наблюдаемый факт без соответствующих данных.

Метафоры допустимы только после точного фактического описания и не должны усиливать уверенность вывода.

## 7. Контроль качества и отказоустойчивость

### Полный анализ запрещён, если

- дата исходного CSV не совпадает с датой отчёта;
- `Quality_Status = FAIL`;
- отсутствует готовый `indicator_levels`;
- неизвестен или неприменим форвардный сдвиг, необходимый для переноса уровней на MT5;
- отсутствуют обязательные экспирации или MDD-поля;
- обнаружено несоответствие актива, контракта или единиц измерения.

В таком случае выводится блок «Анализ заблокирован» с конкретными причинами. Торговые сценарии и ордера не публикуются.

### Ограниченный анализ

При `WARN`, `DEGRADED` или аномалии:

- предупреждение помещается в паспорт и итог;
- спорные уровни маркируются;
- уверенность понижается минимум на одну ступень;
- точные торговые параметры не публикуются, если дефект затрагивает их расчёт.

## 8. Уверенность вместо выдуманной вероятности

Числовые вероятности разрешены только при наличии описанной и проверенной статистической модели с исторической калибровкой. В остальных случаях используется шкала:

- **Высокая** — несколько независимых подтверждений, нет существенных противоречий;
- **Средняя** — есть подтверждение структуры, но присутствует значимый альтернативный фактор;
- **Низкая** — данные неполны, цикл сменился либо вывод держится на одном признаке.

Для каждого сценария обязательно перечислить подтверждения и противоречия.

## 10. Структура недельного отчёта

Недельный отчёт также создаётся только по запросу. Он включает:

- даты начала и конца недели;
- календарь дневных и глобальных экспираций;
- возможные точки rollover;
- глобальные уровни индикатора и диапазоны R68/R95 с корректными ролями;
- сценарии развития недели с условиями активации и инвалидации;
- перечень данных, которые необходимо обновлять перед каждым дневным решением.

Недельный отчёт не заменяет дневной и не считается торговым сигналом на каждый день недели.

## 11. Формат хранения в дашборде

Используется схема `analysis.json` версии 2:

```json
{
  "schema_version": 2,
  "generation_mode": "on_demand",
  "retention_days": 7,
  "updated_at": "2026-08-03T08:45:00+03:00",
  "assets": {
    "EUR": {
      "daily": {
        "2026-08-03": {
          "report_date": "2026-08-03",
          "generated_at": "2026-08-03T08:45:00+03:00",
          "source": "on_demand",
          "content": "# EURUSD — план на 03.08.2026"
        }
      },
      "weekly": {
        "2026-08-03": {
          "week_start": "2026-08-03",
          "week_end": "2026-08-07",
          "generated_at": "2026-08-03T08:45:00+03:00",
          "source": "on_demand",
          "content": "# EURUSD — обзор недели 03.08.2026–07.08.2026"
        }
      }
    }
  }
}
```

Правила записи:

- дневной ключ — точная дата `YYYY-MM-DD`;
- недельный ключ — понедельник соответствующей недели;
- обновляется только явно запрошенный актив и период;
- остальные даты и активы сохраняются без изменений;
- отчёты хранятся 7 календарных дней включительно; записи старше 7 дней автоматически удаляются по ключу периода;
- пустая запись не создаётся;
- отчёт обязан содержать идентификатор даты, совпадающий с ключом;
- интерфейс показывает только точное совпадение даты или недели и никогда не ищет отчёт по названию дня недели.

## 12. Финальная самопроверка

Перед сохранением подтвердить:

1. Дата отчёта, дата CSV и выбранная дата дашборда не перепутаны.
2. Все числовые уровни присутствуют в `indicator_levels` и совпадают с MT5.
3. Daily/Global expiry и rollover учтены раздельно.
4. MDD, Zero Gamma и R68/R95 интерпретированы по своим формулам и ролям.
5. Факты отделены от гипотез, а уверенность объяснена.
6. При проблемах качества торговый план заблокирован или ограничен.
7. Старые отчёты сохранены по своим датам и не могут отображаться как новые.
8. Манифест `indicator_levels` экспортирован индикатором после загрузки CSV той же даты, а не рассчитан агентом самостоятельно.
